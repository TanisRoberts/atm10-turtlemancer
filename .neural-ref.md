# ATM10 reference: Neural lab (Hostile Neural Networks, Oct 2026)

Companion to claude/atm10-computercraft-reference.md (same workflow: clone, change, push to main, mirror). Adds the computer role **neural** (`computer/neural/neural.lua`, run `neural`, name "Neural lab"), storage **dock keep lists** and sorting paused while picking a chest, and mainframe hooks. Manifest computer order: mainframe, storage, smelter, foreman, gps, plastic, neural.

## HNN facts (read from the mod's source, branch 1.21, v6.5.1; ATM10 7.2 shipped 6.5.0)
- Registry/peripheral names: `hostilenetworks:sim_chamber_N`, `hostilenetworks:loot_fabricator_N`. Both expose the item handler and energy (any side) to CC. Items: `hostilenetworks:data_model` ("Blaze Data Model", stack 1, its data component changes every run), `hostilenetworks:prediction` ("Blaze Prediction", per-mob component), `hostilenetworks:prediction_matrix`, generalized predictions `hostilenetworks:{overworld,nether,end,twilight}_prediction`.
- Chamber slots (CC 1-based): 1 model (insert only, only data models), 2 input (insert only, must match the model's input = matrix), 3 base drop (generalized prediction), 4 mob prediction (3 and 4 extract only). **A computer can't take the model or matrices back out.** Mode (Inference/Training) and redstone (Ignored/High/Low) are GUI-only. Inference run = 240 ticks (12 s), Training 300 ticks at 1.2x cost; one matrix consumed at the START of a run; energy drawn only while a run is going (idle = 0). In 6.5 a base drop comes every Inference run (6.4: only on failed runs). Training mode makes nothing and upgrades the model (+1 data per run).
- Fab slots: 1 prediction in (insert only), 2..17 out (extract only). 60 ticks + 256 FE/t per prediction; no prediction = no power. Drop choice is saved **per model inside each fab** (FabSelection: Fixed index or Queue), GUI-only; no selection = does nothing. The Fabrication Directive item copies a fab's selections. 6.4 added Queue mode and fab redstone control.
- Buffers: chamber 2,000,000 FE, fab 1,000,000 FE (config). Costs: blaze 256 FE/t, enderman 512, zombie 128, wither 2560.
- Default tiers (data_models/model_tiers): faulty 0 data (can't sim), basic 6 (5%), advanced 54 (22%), superior 354 (65%), self aware 1254 (100%); kills give 1/4/10/18 data at faulty/basic/advanced/superior. ~100 blaze kills blank -> Self Aware; Training mode needs ~1254 matrices.
- Blaze drops: 16 blaze rods or 2 reliquary:molten_core (optional). Enderman: 16 ender pearls, 1 end crystal, evilcraft ender tear, reliquary nebulous heart. Default prediction matrix recipe makes 16 (iron, gold, glass panes, clay); ATM10 may change recipes/tiers: check JEI.

## neural.lua
- Own cable (storage would eat the chambers). Classifies cable names: sim_chamber, loot_fabricator, redstone_relay / redstone_integrator (lamps), furnator, other hostilenetworks blocks ignored, other energy_storage = cells (all summed; a full-block wired modem joins every cell touching it), one chest/barrel = dock. Several (lab cable joined to storage): the one storage's broadcast lists in `docks`, else none + note asking for `DOCK=` (never guesses a storage barrel).
- **Pairing**: cfg.links[chamber] = {f, l}, sticky; `PAIRS=c:f[:l], ...` (by name numbers) override; new chambers get the lowest-numbered free fab/lamp in order (CC numbers peripherals per type in connection order). A replaced fab joins the chamber that lost one.
- **Per pass** (TICK 2 s, plus at once on peripheral attach/detach): base drops -> dock; fab outputs -> dock (learns item = last output name; cfg.items[chamber]; switch remembered for the page); decide want: force on/off, learning (item unknown) = run, no storage counts = WITHOUT_STORAGE (stop), else stock (storage broadcast items + dock) vs cap from neural.txt (full id or path; `off` = 0; DEFAULT_KEEP 256) with hysteresis (on below RESTART_AT 90%, off at cap, cfg.on remembers). **Power % = min(cells summed, chambers' own buffers)** (Oct 2026 fix: with no cell, full idle fabs hid empty chambers at ~33% so the Furnator never fed; monitor shows `Sims n%` when chambers lag the cells; NO POWER alert says 'cells are at X%, is it on the power line?' when cells >= 20%). Low power (< LOW_POWER 10%): only the wanting column with the lowest stock/cap runs.
- **Feeding**: predictions chamber slot 4 -> fab slot 1 up to FAB_HOLD (2) while running/learning; matrices dock -> chamber slot 2 up to MATRIX_HOLD (1). Stopped columns keep ONE prediction banked (bank-building runs) for checks. **CHECK** (card button, `check n`) pushes one banked prediction through (or runs sims until one exists). Periodic check after PROBE_EVERY (15) min, doubling while the drop is unchanged up to PROBE_MAX (240), reset by a change or by running. Measured: ~2 batches per stopped column in 4 quiet hours.
- **States**: RUNNING (lamp steady), AT TARGET / OFF / WAIT POWER / PAUSED (lamp off), blinking: NO MODEL, NO FAB, LEARNING, CHECKING, NO MATRICES, STUCK (wanting, has a matrix, none used for STALL_AFTER 90 s), NO POWER (stuck + chamber < 20k FE), TRAINING? (4+ matrices used with no base drop or prediction), FAB NO POWER / PICK A DROP / DOCK FULL (fab holding predictions 30 s with no progress), NO COUNTS. Problems -> mainframe alerts (`neural:<key>`): stuck/power/training/fabpower/pick per chamber, matrices, dock, dockfull, counts, fuel.
- **Furnator**: fed charcoal > coal > coal block from the dock up to FURNATOR_KEEP (8) only while power < FUEL_BELOW (30%). Never blaze rods.
- **Lamps**: relay setOutput on all six sides; blink 0.75 s; only calls setOutput on change.
- neural.env (butler.env rules): TICK, DEFAULT_KEEP, RESTART_AT, MATRIX_HOLD, FAB_HOLD, PROBE_EVERY, PROBE_MAX, STALL_AFTER, LOW_POWER, FUEL_BELOW, FURNATOR_KEEP, WITHOUT_STORAGE, DOCK, PAIRS. neural.txt: written on first run (blaze_rod 512, ender_pearl 256), re-read on change; the monitor's -/+ (step 64, 16 under 256) rewrite the item's line. neural.cfg: paused, links, items, on, force, stats {runs, preds, made}, made per item.
- Monitor (touching the computer): overview cards (17+ chars each, as many per row as fit, paging), tap card -> page (target -/+, AUTO/ON/OFF, CHECK, stats, names, its problems); PAUSE/RUN top-right; works down to 29x17.
- Network (wireless/ender): hears storage's `storage` broadcast for counts; broadcasts `{type="neural", id, label, state, note, lines, problems, columns={mob,state,item,stock,cap}, power, paused}` every 3 s on tanis-base; obeys `neural_cmd {to=id, want=pause|go}`.

## Other changes
- **Direct mode (Oct 2026, Tanis's setup: lab on the storage network):** scan sets `L.direct` when storage's broadcast `mainInput` is present on the cable (and DOCK= blank). Then `L.out` = that input chest: fab outputs + base drops are pushed into it (storage sorts them); stock adds its contents; matrices/fuel counts come from storage's broadcast; supplies are requested with `rednet.send(storageId, {type="neural_ops", id, ops={ {op="fill", to, item, count<=64, slot} }})` sent from netLoop, one ask per target per 8 s. storage `runNeuralOps` (via the jobs queue, reply `neural_done {id, results}`) only fills `hostilenetworks:sim_chamber*` slot 2 with prediction matrices and `*furnator*` with charcoal/coal/coal block (SMELTER_RESERVE kept). Otherwise (own cable) the dock logic below applies. Terminal `list` shows "Drops to:".
- **Stuck drops (Oct 2026 fix):** Tanis saw 112 rods sitting in a fab while the lab said 19/512 (stock didn't count fab outputs; drops weren't reaching the dock). Stock now = storage + dock + every fab's leftover outputs (`heldOut[chamber]`). A fab left holding 32+ it couldn't move -> state NO DOCK (L.dock nil) or DOCK FULL (push short), alerts `dock` / `dockfull`. Overview monitor row 5 shows the most useful problem in words.
- **Joined cables (Oct 2026 fix):** Tanis's chambers showed up in storage (data model listed). storage `isMachine` now also skips names starting `hostilenetworks:`, `powah:`, `industrialforegoing:` (never storage, never filled), and its status broadcast carries `docks = cfg.docks`.
- storage: `cfg.dockKeep[dock] = {[item id] = n}`. deposit() leaves kept items in a dock, topUpDocks() tops them up from storage. `/dock` on a new dock asks what to keep; on an existing dock: 1 = change the keep list, 2 = remove. Keep items by path (`prediction_matrix 64`, looked up in storage then every chest on the cable) or full id; `<item> 0` stops keeping. `/inputs` lists keeps. **pickChest now sets `picking`**, waits for the current sorting pass and the worker skips passes until it returns (reset after every command), so a dock's test item isn't sorted out mid-pick (bug fixed).
- mainframe: base_link `_G.NEURAL / NEURAL_SEEN`; board row "Neural lab" (note + power); island `neuralSilent` + `neural:<key>` alerts; chat `island neural` (8 status lines) and `island neural pause|go` (alias `lab`).
